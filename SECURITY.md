# Security Policy

## Our Commitment

The Collective takes security seriously. As a portal focused on OSINT methods and AI verification, we maintain strict boundaries to ensure this resource cannot be misused for harmful purposes.

## Supported Versions

This repository contains documentation and workflows. Security updates apply to:

- GitHub Actions workflows
- Issue/discussion templates
- Documentation that could impact user safety

## Reporting a Vulnerability

### What to Report

We want to know about:
- **Workflow vulnerabilities** — GitHub Actions exploits, permission issues
- **Information disclosure** — Accidental exposure of sensitive data in documentation
- **Automation abuse** — Ways to bypass safety checks in issue templates
- **Documentation that enables harm** — Content that could facilitate illegal activity
- **Privacy concerns** — Issues with how questions/answers are handled

### How to Report

**DO NOT** open a public issue for security vulnerabilities.

Instead:
1. **Email:** Contact Andrea or the collective facilitators directly (contact info in repository settings)
2. **GitHub Security Advisory:** Use the "Security" tab to privately report vulnerabilities
3. **Direct Message:** Contact @Collective-Conversation privately

### What to Include

- **Description** of the vulnerability
- **Steps to reproduce** (if applicable)
- **Potential impact** on users or the collective
- **Suggested fix** (if you have one)

### Response Timeline

- **Acknowledgment:** Within 48 hours
- **Assessment:** Within 7 days
- **Fix or mitigation:** Depends on severity (critical issues prioritized)
- **Disclosure:** We'll coordinate public disclosure timing with you

## Security Best Practices for Users

### When Asking Questions
- **Never share real PII** — Use redacted, anonymized examples only
- **Don't post live investigation details** — Abstract the scenario
- **Avoid real URLs** — Use example.com or describe patterns instead
- **Strip metadata** — Clean EXIF data from uploaded images

### When Answering Questions
- **Don't enable illegal activity** — If a question is asking for harm, refuse it
- **Flag unsafe questions** — Report violations to moderators
- **Verify before advising** — Don't guess on security/legal matters
- **Cite sources** — Help users verify independently

## Out of Scope

These are not security issues for this repository:
- General GitHub platform vulnerabilities (report to GitHub)
- Issues with third-party tools mentioned in answers
- Theoretical attack vectors with no practical impact
- Questions about the collective's operational security (use Meta discussions)

## Security Philosophy

The Collective operates on these principles:
1. **No Targeting** — We refuse questions that identify specific individuals
2. **Education Only** — We teach methods, not exploits
3. **Legal Boundaries** — We comply with US and international law
4. **Transparent Limits** — We clearly state what we won't answer

If you see a question or answer that violates these principles, report it immediately.
